# 竞技场挂机（自动点开始匹配，常驻守候）

用途：打开「竞技场」面板后，自动等待「开始匹配」按钮出现并点击；打完一局回面板、
匹配失败重试、队伍重组之后按钮再次出现就再点一次。**任务不会自行结束**，要收工点
「停止任务」。

识别器 `jingjichang`：全屏 OCR + **锚定关键词**（整段 `^\s*开始匹配\s*$`，外加
拆行半行 `^\s*开始\s*$` / `^\s*匹配\s*$`，见 `utils.ocr_button.expected_patterns`），
单轮最多等待 600 秒（一场战斗的时间），2 秒一帧。命中即返回按钮命中框，由
pipeline 节点 Click（与擂台 / 剑会同一套写法，公共部件都在 `utils/ocr_button.py`）。

## 为什么不能直接点框架给的那个框

MaaFramework 的 OCR `expected` 是**子串**正则（`boost::regex_search`），
`cherry_pick()` 默认取**最靠左**的命中框：面板右下角那行说明文字
「开始匹配后自动进入对局」同样命中，而且排在按钮上方偏左时，Click 就点在
文字上（本地空跑复现：旧版点 (1098, 564)，按钮矩形是 (1049, 597, 130, 49)）。
锚定 + 候选框复查之后，说明行连候选都不是。

固定比例 ROI `[0.76w, 0.75h, 0.18w, 0.23h]` 是按一张横屏截图量的，换分辨率 /
竖屏会整块错开，把按钮排除在扫描区外 —— 现在默认全屏。

## 真机按钮文字排两行（918x500 实测）

竞技场的按钮文字是**上下两行**，OCR 各读一个框：

```
[1038, 577, 63, 37] 开始
[1042, 608, 59, 34] 匹配
```

整段锚定正则一个都不命中，现象就是「按钮明明在屏幕上，任务却一直在蹲、从没点过」。
所以 `expected` 用 `expected_patterns()`（整段 + 半行），再由 `pick_button_box`
把上下两框合成一个按钮框：下框在上框下方、水平重叠 ≥ 较窄行的 50%、行距
≤ 行高的 0.8 倍、两行宽度比 ≥ 0.4，点合框中心。擂台 / 剑会共用这套判定，三个
任务一起受益。

单行按钮（其它机型）仍走整段匹配，不受影响。

## pipeline

`jingjichang`（入口，timeout -1）→ `竞技场-保持匹配`（Custom 识别 + Click，
`next` / `on_error` 都跳回自身）。命中点了继续守，没命中下一帧再看，**任务不会
自行结束**；要收工点「停止任务」，识别器收到停止请求立即退出本轮守候。

节点 `timeout` 设成 -1：连续蹲守可能远超节点默认超时，不能被框架掐掉。

## 可选参数（custom_recognition_param）

`jjc_enabled` 关掉该节点、`jjc_expected` 自定义锚定关键词、`jjc_roi` 绝对像素
ROI、`jjc_roi_ratio` 按比例 ROI（默认全屏，免换算）、`jjc_threshold` OCR 阈值、
`jjc_max_wait` 单轮等待秒数、`jjc_interval` 轮询间隔、`jjc_click_cooldown`
连击冷却（避免同一面板连点），`jjc_notify` 命中通知。
