# 竞技场挂机（自动点开始匹配，打满 N 次结束，可设常驻）

用途：打开「竞技场」面板后，自动等待「开始匹配」按钮出现并点击；打完一场回来
继续蹲，打满 `jjc_max_clicks` 次（默认 10）任务完成。

识别器 `jingjichang`：全屏 OCR + **锚定关键词**（`^\s*开始匹配\s*$`，只有整段
文本就是「开始匹配」才算命中），单次按钮等待最多 600 秒（一场战斗的时间），
轮询间隔 2 秒。点击在识别器内直接执行（点按钮框中心），计数满
`jjc_max_clicks` 即返回成功；中途超时返回失败由 pipeline 重试，**计数挂在类上，
不会因为重新进入分析而清零**。

## 为什么不能直接点框架给的那个框

MaaFramework 的 OCR `expected` 是**子串**正则（`boost::regex_search`），
`cherry_pick()` 默认取**最靠左**的命中框：面板右下角那行说明文字
「开始匹配后自动进入对局」同样命中，而且排在按钮上方偏左时，Click 就点在
文字上（本地空跑复现：旧版点 (1098, 564)，按钮矩形是 (1049, 597, 130, 49)）。
锚定 + 候选框复查之后，说明行连候选都不是。

## pipeline

`jingjichang`（入口，timeout -1）→ `竞技场-开始挂机`（Custom 识别，点击在识别器
内完成）。打满次数 → 回主界面判定收工；超时 → 跳回继续蹲（计数保留）。

节点 `timeout` 都设成 -1：连续蹲满 10 场可能远超节点默认超时，不能被框架掐掉。

## 常驻模式

`jjc_max_clicks` 设为 `0`（或负数）表示**不限次数**：只要出现按钮就一直点，
任务不会自行结束，直到手动「停止任务」（识别器收到停止请求立即退出本轮守候）。

## 可选参数（custom_recognition_param）

`jjc_enabled` 关掉该节点、`jjc_max_clicks` 打满次数（0 = 常驻）、
`jjc_expected` 自定义锚定关键词、`jjc_roi` 绝对像素 ROI、
`jjc_roi_ratio` 按比例 ROI（默认全屏，免换算）、`jjc_threshold` OCR 阈值、
`jjc_max_wait` 单次等待秒数、`jjc_interval` 轮询间隔、
`jjc_click_delay` 点击后等待（兼作连点节流）、`jjc_notify` 每次点击通知。
